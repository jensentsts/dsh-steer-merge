# DSH 插话合并

> 插件集导航与市场索引：https://github.com/jensentsts/dsh-independent-plugins


在已有插话进入下一步时，收集连续抵达的插话，一次提交给当前会话。来自 DSH 和不同消息渠道的插话按到达顺序进入同一个模型步骤，消息、发送者和附件仍各自保留。消息路由暂时排入下一轮的插话也会合并；明确选择排队的消息继续按原顺序处理。

默认在最后一条消息到达后等待 500 毫秒，持续到来的消息最多收集 2000 毫秒后进入下一步。可设置 `windowMs` 为 0–2000、`maxWaitMs` 为 0–10000 毫秒，最大等待时间至少为一个收集窗口；`enabled` 可关闭，`windowMs` 为 0 时直接处理。普通消息无需等待。合并适用于 DSH 原生插话，也可识别消息路由服务的回执，不依赖 QQ 桥接。原生消息路由的回复目的地判定继续生效。

插件使用当前 DSH 0.2.2-rc.1 的 inbox `claim` 实现，以保留官方的持久化和消息生命周期事件。运行环境如果缺少此操作，插件会自动保留原队列行为。不要跨 DSH 大版本假定它仍然可用。
